Bîr — current prototype and proposed Android + iPhone architecture
================================================================

CURRENT IMPLEMENTATION
The current product is an HTML/JavaScript browser prototype, not a Flutter/native project, APK or IPA. It includes a three-language interface (ckb/ar/en), local study progress, deck/card browsing and editing, new decks and manual card creation.

Deck deletion and speech in the PC prototype
- Confirmed deck deletion moves the deck, its cards and their review history/progress out of active study into persistent local Deleted decks. Any saved deleted deck can be restored with its progress. The JSON backup includes this recoverable data.
- Manual study controls read the question, answer or definition aloud and stop speech. Settings select the content language (automatic/en/ckb/ar) and a device/browser voice. Kurdish voice availability is not guaranteed; no audio files are generated. Reading-language and interface-language choices do not translate content.

File import is now implemented in the PC prototype:
- APKG is read by a local Python preview server and an installed Anki 26.9 native helper. On this Windows PC the helper uses Anki 26.9.3's Python 3.13 runtime at %LOCALAPPDATA%\Programs\Anki (currently %LOCALAPPDATA%\Programs\Anki).
- TXT, TSV and CSV are parsed in the browser, with separator/header detection, field mapping and a card preview before changes are committed.
- Import can target one deck or retain the source deck structure. Duplicate handling updates matching content while retaining the card's existing Bîr review progress, or skips matching cards.
- APKG supplies text and supported raster images (PNG/JPEG/WebP/GIF/AVIF). Reversed cards and cloze variants are rendered as individual study cards. Original dynamic templates, source styles, JavaScript, audio, SVG and source learning/review history are not imported.
- Text files import text only, without embedded media. Files are processed on this PC, without an external upload. APKG extraction uses an isolated temporary Anki collection, not the user's personal Anki collection.
- The JSON backup restores cards, local progress and settings. It does not embed images; keep the entire application folder, including media/ and imported images, together with the JSON backup.

Run from the workspace:
    python server.py --port 64008
Open http://127.0.0.1:64008/ and keep the local server running for APKG. If the application folder is copied or renamed (for example Bir), run python server.py --port 64008 inside that folder. Opening index.html directly supports text import, editing and study, but not APKG. Saved browser data belongs to the browser/address used.

MOBILE STATUS
Android and iPhone are confirmed goals. The shared Flutter phase described below remains future work. Flutter SDK is not installed on this PC yet. The current import helper depends on a Windows-installed Anki runtime and must be replaced or integrated appropriately for mobile; it is not a mobile backend.

PROPOSED SHARED APPLICATION
Use Flutter/Dart for one shared product UI and domain layer, with platform adapters where required. Keep three primary destinations: Today, Decks and Progress. Put advanced controls in contextual menus and Settings.

Separate the proposed code into:
- UI and localization: screens, accessible controls, themes and translated resources.
- Domain: Deck, Note, Card, MediaAsset, ReviewEvent and Settings, with stable IDs and explicit schema versions.
- Repositories: transactional local storage and media-file access.
- Scheduler adapter: an isolated interface for a verified spaced-repetition engine.
- Transfer adapters: backup, restore, import/export and, later, synchronization.
- Speech adapter: platform text-to-speech, available-voice discovery, language selection, cancellation and feedback when no suitable voice is installed.

LOCAL DATA AND MEDIA
Preserve recoverable deck deletion as a separate persisted collection, including the deck's cards, review state and history. Include it in complete backups and test restoring several deleted decks after a restart.
Use mobile SQLite for structured data and an application-managed directory for media. Keep review events and scheduling state separate from content. Validate database migrations and restore operations. Preserve the distinction between updating an existing local card and importing scheduling from another application.

A future complete backup should contain a manifest, database/content and all referenced media, with a tested restore path. This differs from the current prototype's JSON export, which requires keeping the application/media folder separately.

THREE LANGUAGES
Use localized resources for ckb (Sorani Kurdish), ar (Arabic) and en (English). Supply custom widget translations where framework defaults are insufficient. Test RTL navigation, mixed English/RTL card text, number/date formatting, large fonts and screen readers on both platforms. Interface language and card-content language remain independent.

SCHEDULING AND ANKI COMPATIBILITY
FSRS is not implemented in the prototype. Choose a maintained scheduling implementation after evaluating platform bindings, persistence, licensing and test vectors. Native scheduling must be tested for review grades, time zones, day boundaries and restoring history.

Keep these separate milestones:
1. Port the current text/APKG import workflow to the mobile architecture, preserving content, supported images, stable identity, duplicate handling and local review progress.
2. Broaden compatibility with package versions, richer note types, templates and media using safe extraction and regression fixtures. Current prototype import is limited as described above.
3. Transfer original Anki scheduling/history only after compatibility and round-trip tests pass. Existing Bîr progress preservation during duplicate import does not provide this capability.
4. Evaluate synchronization separately. AnkiWeb compatibility or service access is not implemented or promised by choosing Flutter.

DELIVERY PHASES
1. Establish Flutter tooling, repository and automated checks; rebuild the approved design for Android and iPhone.
2. Deliver an offline native study app with transactional persistence, media, editing and tested complete backup/restore.
3. Integrate and verify the scheduler and mobile import/export adapters, building on the current prototype's import behavior.
4. Add advanced study features and evaluate synchronization after compatibility requirements are agreed.

BUILD REQUIREMENTS
Android tooling can be prepared on this Windows PC. Flutter's iOS build/release workflow requires macOS and Xcode or a suitable Mac build environment. Signing and store distribution are later delivery steps. A native mobile implementation does not follow automatically from the existing web prototype or its Windows Anki helper.


پوختەی کوردی
=============
سڕینەوەی دەک بە پشتڕاستکردنەوە، دەک و کارت و پێشکەوتنەکەی دەگوازێتەوە بۆ «دەکە سڕاوەکان». هەموو دەکە پارێزراوەکان دەتوانرێت بگەڕێندرێنەوە و لە کۆپیی JSONیشدا هەن. دوگمەکانی پرسیار، وەڵام و پێناسە دەقەکە بە دەنگی ئامێر یان وێبگەڕ دەخوێننەوە؛ فایلی دەنگ دروست ناکەن و بەردەستبوونی دەنگی کوردی بە ئامێرەکەوە بەستراوە. گۆڕینی زمانی دەنگ ناوەڕۆک وەرناگێڕێت.

ئێستا هاوردەکردنی APKG لە PC بە سێرڤەری ناوخۆیی و یارمەتیدەری Anki 26.9 کار دەکات. TXT، TSV و CSV لە وێبگەڕدا دەخوێنرێنەوە و پێشبینین و دیاریکردنی ستوونەکانیان هەیە. دروستکردنی دەک و کارت بە دەستیش کار دەکات. کارتە هاوتاکان دەتوانرێت نوێ بکرێنەوە بە پاراستنی پێشکەوتنی هەبوویان لە بیر، یان تێپەڕێنرێن.

هاوردەکردنی APKG سنووری هەیە: دەق و وێنەکانی PNG/JPEG/WebP/GIF/AVIF دێن، و کارتی پێچەوانە و شێوەکانی cloze وەک کارت دەردەکەون. مێژووی خوێندنی سەرچاوە، قاڵبی کارلێککار، دیزاینی سەرەکی، JavaScript، دەنگ و SVG ناگوازرێنەوە. فایلە دەقییەکان وێنەی ناوخۆیان نییە. هەموو کارەکە لە PC ئەنجام دەدرێت و بۆ خزمەتگوزارییەکی دەرەکی نانێردرێت.

فایلی JSON کارتەکان، پێشکەوتن و ڕێکخستنەکان دەگەڕێنێتەوە، بەڵام وێنەی تێدا نییە؛ تەواوی فۆڵدەری ئەپەکە بە media/ و وێنە هاوردەکراوەکانەوە بپارێزە.

وەشانی ئێستا نموونەی وێبە. هێشتا پڕۆژەی Flutter، APK یان IPA دروست نەکراوە. ئەندرۆید و ئایفۆن ئامانجی قۆناغی داهاتوون: ڕووکاری هاوبەشی سێ زمان، SQLite، بەڕێوەبردنی وێنە، سیستەمی تاقیکراوی دووبارەکردنەوە و هاوردەکردنی گونجاو بۆ مۆبایل. FSRS، گواستنەوەی مێژووی خوێندنی Anki و AnkiWeb هێشتا جێبەجێ نەکراون. بۆ دروستکردنی وەشانی ئایفۆن، macOS و Xcode یان ژینگەیەکی گونجاوی ماک پێویستە.

ملخص بالعربية
=============
تُنقل الرزمة المحذوفة مع بطاقاتها وسجل المراجعة والتقدم إلى قسم محفوظ محليًا؛ ويمكن استعادة أي رزمة منه وتضمينه في نسخة JSON. تتيح أزرار الدراسة قراءة السؤال أو الإجابة أو التعريف وإيقاف الصوت. تعتمد القراءة على أصوات الجهاز والمتصفح، وقد لا يتوفر صوت كردي. لا تُنشأ ملفات صوتية ولا يُترجم المحتوى عند تغيير لغة القراءة.
